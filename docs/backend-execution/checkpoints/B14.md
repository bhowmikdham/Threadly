## Bounded scope and prerequisites

B13's deterministic slot read API is merged. B10's four reviewed compound kernels
exist, but automatic/broader Calendar graphs do not; B14a does not pretend that
broader prerequisite is complete. Install the owned negotiation state independently
before adding assistant scheduling orchestration in B14b. B12/B13 live gates remain.

Create a thread-bound negotiation; adopt a fresh nonempty owned slot query into an
immutable offer revision; explicitly select a stored option; re-read exact availability;
close or replace offers while preserving historical choices. Expose current usability
and blockers separately from historical state. Selection never approves booking.

The persisted selection receipt precedes Google reads. Account → preferences → thread
→ negotiation locks fence publication; no caller DB transaction spans reads. Concurrent
duplicates share one check. New email/preferences, expiry, replacement or close prevent
late selection publication. Sync records actual source update time, so transaction-start
clock values cannot let an older query pass a source-change adoption check.
