## Implementation sequence

1. Implement pure interval functions with UTC normalization and IANA display zone: merge/clip busy periods, apply buffers, generate working windows, enforce duration/notice and choose up to three deterministic candidates.
2. Resolve request-relative date anchor from persisted request/message time with explicit origin; never datetime.now at retry. Treat ambiguous AM/PM, zone or duration as missing input unless a confirmed displayed preference applies.
3. Handle DST gaps/folds and cross-midnight working windows explicitly. Persist option IDs, preference/source versions, checked_at, expiry and assumptions.
4. Return zero/fewer than requested slots honestly; unknown calendar coverage prevents a confident availability claim.
5. Add a bounded read endpoint/handler used by scheduling; no event reservation or write occurs.

## Acceptance assertions

Implement independent tests for these behaviors. Record each assertion in the checkpoint;
do not mark a live assertion passed using only a mock. Apply all relevant QUALITY-GATES checks.

- **B13-A1:** Independent interval fixtures cover overlap/nesting/adjacency, all-day busy, buffers, weekends, notice and fewer-than-three slots.
- **B13-A2:** Australia/Melbourne DST gap/fold, UTC conversion and participant zones produce correct instants or clarification.
- **B13-A3:** Delayed task/retry resolves tomorrow using original anchor; 4 without AM/PM does not silently become 16:00.
- **B13-A4:** Changing calendar/preference version or expired evidence invalidates stored slot offers.
- **B13-A5:** No overlap between any proposed slot and expanded busy intervals; metamorphic tests show adding busy time cannot add availability.
