## Behavior delivered

Two strict explicit templates (`summary_then_reply`, `summary_then_compose`) enter
`POST /assistant/compound-requests`. Ownership, source/target and recipient prerequisites
are validated before enqueueing one durable task. The fixed handler set and saved
release are validated before inference; arbitrary graphs/actions/Flow IDs are rejected.
There is no new natural-language planner and no classifier-selected template fallback.

The summary and final draft each have their own revision stream. Step state, attempts,
input/output hashes and pinned release persist. Retrying a failed draft reuses the
valid summary. Source changes stop execution and require a fresh request; historical
output is not edited or recomputed in place. Every publication checks the task lease
and source; final draft and task success commit together. Draft edits/reviews remain
compatible and the task final-result pointer tracks the current draft.
