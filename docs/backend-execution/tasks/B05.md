## Implementation sequence

1. Implement action job claim/fence/expiry and short transaction preflight. Refresh credentials/perform source reads outside DB locks, then compare versions again before committed dispatch intent.
2. Call Gmail with frozen approved bytes and thread ID only. No model call, MIME regeneration or recipient expansion in executor.
3. Persist confirmed provider ID/result or sanitized definite failure; any may-have-dispatched timeout, disconnect, malformed success or worker crash becomes outcome_unknown.
4. Expired generation leases must never pick up action jobs; expired dispatch leases become reconciliation work. Disable automatic HTTP retry for write calls.
5. Add separate default-off write flag and optional worker service/config. No live activation in this PR; B06 is a hard enabling dependency.

## Acceptance assertions

Implement independent tests for these behaviors. Record each assertion in the checkpoint;
do not mark a live assertion passed using only a mock. Apply all relevant QUALITY-GATES checks.

- **B05-A1:** Capture HTTP request bytes and compare to stored approved payload; mutated live draft cannot alter an in-flight payload.
- **B05-A2:** Two workers/expired leases cannot issue a second send; stale completion cannot overwrite newer reconciliation state.
- **B05-A3:** Inject crash before/after dispatch-intent commit, timeout before/after simulated provider acceptance, 401/403/429/5xx and invalid JSON success.
- **B05-A4:** No DB row lock is held during blocked HTTP call; cancellation/edit can record correct post-cutoff state.
- **B05-A5:** Disabling writes or revoking account capabilities prevents new dispatch while leaving unknown attempts visible.
