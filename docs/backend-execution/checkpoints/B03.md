## Behavior and decisions

Owned proposal/read endpoints derive a saved send candidate from the current final
edited draft. Primary verified Google account, recipient/body validation, effective
context and reply header/version checks precede persistence. Freeze UTF-8 plain-text
MIME, Date, Message-ID, exact hashes and 30-minute expiry once per proposal key.
Duplicate requests reuse the stored candidate; edits supersede pending candidates.
Read responses include current blockers and expose Bcc to the owner, but omit raw
MIME. Review/preview does not authorize sending; no approval/job/attempt is created.

API, diagram, storage schema, supported subset and B04 mapping:
[email action previews](../../email-action-previews.md). No migration or prompt,
model, Flow, new dependency or configuration changes.

## Focused second review

- Owned artifact and action queries; no arbitrary payload, user ID, sender or MIME
  authority accepted over HTTP. Sanitized validation errors/events omit private data.
- Task-first locks serialize edits/replay; transaction rollback leaves no candidate
  or event. No helper commit/network call. Source/account checks are versioned local
  snapshots; future approval and dispatch must recheck, not trust an earlier preview.
- Fixed source lookup to use the published artifact's effective context, preserving
  clarification and user-edit source binding instead of the task's original context.
- Require consistent draft mode/thread ref/envelope; missing reply metadata cannot
  silently become new mail. Exact subject binding follows existing draft semantics.
- Header subset is deliberately conservative. Legacy incomplete metadata requires
  refreshed context. References chains are bounded and never silently truncated.
- Saved bytes include Bcc for future Gmail delivery; public owner preview makes Bcc
  explicit. Provider stripping/delivery/thread membership require controlled live tests.
- Expired/replaced actions remain readable with blockers and original bytes. New key
  is a new proposal, not provider idempotency. No sender deduplication claim.
- No public approve/send route, action worker or enqueued action job. Existing
  capability flags remain truthful: send/Calendar unavailable regardless of scope.
