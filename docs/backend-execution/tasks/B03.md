## Implementation sequence

1. Add the artifact-to-action proposal endpoint with request/revision preconditions. Read artifact.draft_envelope; never use original task recipients after edits.
2. Build deterministic plain-text MIME with Python email primitives, frozen Date/Message-ID, validated sender/To/Cc/Bcc and safe encoding; persist exact bytes/hash plus user preview.
3. Validate reply thread identity, References/In-Reply-To chain and source version from owned synced metadata; pin sender/capability versions. If exact headers are unavailable, stop for refresh/rebinding.
4. Preserve unresolved-fact/placeholder checks, reject unsupported attachments/aliases, and ensure UI distinguishes Mark reviewed from a send preview.
5. Specify legacy integer draft linkage or keep legacy routes explicit 501; no second independent authority for outgoing content.

## Acceptance assertions

Implement independent tests for these behaviors. Record each assertion in the checkpoint;
do not mark a live assertion passed using only a mock. Apply all relevant QUALITY-GATES checks.

- **B03-A1:** Editing Bcc/To/body/subject produces a different proposal/hash; replay cannot substitute the original task envelope.
- **B03-A2:** Header injection, Unicode/header folding, duplicate addresses and malformed reply IDs are handled by independent MIME parse assertions.
- **B03-A3:** MIME bytes, Date and Message-ID remain stable across proposal reads/retries; user-visible envelope matches submitted intended recipients.
- **B03-A4:** Stale source or other-owner artifact cannot produce an action; source email instructions cannot create an approval.
- **B03-A5:** Missing headers, unresolved placeholders, unverified sender alias and attachment refs yield explicit blockers, not silently stripped fields.
