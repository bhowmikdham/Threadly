## Implementation sequence

1. Define versioned plan content with stable item IDs, dependencies, optional owners/deadlines, evidence and explicit/inferred/confirmed status.
2. Validate DAG, dates/timezones and allowed source refs deterministically; unknown owner/deadline remains unresolved.
3. Add plan revision/accept-selection operations with optimistic versions and idempotency. Accepting internal work does not send or book anything.
4. Generate a linked draft from only selected confirmed commitments; edits supersede dependent proposals and preserve historical plan evidence.
5. Add capabilities, prompts, replay fixtures and frontend examples using existing artifact streams.

## Acceptance assertions

Implement independent tests for these behaviors. Record each assertion in the checkpoint;
do not mark a live assertion passed using only a mock. Apply all relevant QUALITY-GATES checks.

- **B11-A1:** Dependency cycles, impossible dates, unknown evidence and cross-owner item IDs are rejected.
- **B11-A2:** Inferred promises remain unconfirmed until explicit selection; plan text cannot itself authorize external actions.
- **B11-A3:** Concurrent plan edits/acceptance cannot confirm a superseded item version.
- **B11-A4:** Linked draft contains only selected commitments and valid evidence; unselected inferred deadline is not stated as fact.
- **B11-A5:** Restart/replay preserves accepted item identity and does not create duplicate commitments.
