## Delivered behavior

`read_options` selects one bounded operation through the existing task API. Help
and search execute natively; rewriting uses the established masked model adapter
with only the selected body. Search never interprets Gmail query syntax or expands
source scope. Results have exact backend evidence IDs/quotes and accurate partial
coverage. A rewrite is a text suggestion, never a sent message or a saved email draft.

The read worker checks source ownership/version/existence before generation,
rechecks while fencing publication, and rejects stale results on artifact retrieval.
No database transaction spans inference. Typed options are frozen in `read_input`;
release metadata pins read schemas, prompt, limits, policy and model configuration.
Absent options preserve old request hashes and releases. Source deletion cascades
through existing owned capture/task relations; changed/deleted messages report stale.

See [runtime contract](../../assistant-bounded-reads.md) for examples and diagram.

## B09b follow-up — scoped local mailbox search

Branch `codex/scoped-mail-search`, verified base `9b3b14e8fa71086224bca585a7566ff29dd3775d`
(merged PR #21). This slice adds `POST /assistant/mail-search`, an explicit native
read endpoint across local threads, with required query/folder/date window, exact
bounded excerpts, source versions and honest sync coverage. No durable task,
model call, Gmail request, action or new search-history storage is introduced.
[Full API and rollout](../../assistant-mail-search.md).

The service locks the owned user row in shared mode while selecting sync version
and results; sync holds it exclusively when committing. Signed keyset cursors bind
owner, query/folder/date scope, policy, sync version and original 15-minute expiry.
A new sync invalidates subsequent pages. Parameterized literal text matching cannot
become SQL, regex, a provider URL or a tool call. Folder membership uses actual
saved labels; legacy/unknown labels are not inferred from sender identity.

Acceptance extension: B09-A1 now includes positive two-owner queries with overlapping
provider IDs, signed cross-owner/scope rejection and query injection fixtures.
A2 includes explicit time/folder restrictions, unavailable metadata, partial local
coverage, quote clipping and no-match wording. A4 remains native with no executable
source interpretation. A5 includes cursor tamper/expiry/version and actual PostgreSQL
shared-lock contention/error tests. Persistent entities/commitments and broad answer
quality remain unfinished, so B09/T09 stay in progress.

Initial focused run found HTTP strict datetime parsing rejected JSON ISO strings,
and index reflection disagreed with explicit collation in the tie-break expression.
Fixed by explicit ISO parsing before timezone validation and a stable internal-row-ID
tie breaker, preserving visual-message ordering elsewhere. **17 focused search and
migration tests passed**, zero skips, including empty/representative upgrade and
schema parity. Final regression: **472 passed, zero skips**, including 16 new
search tests. Ruff, both documentation validators, generated cards and whitespace
checks passed. Two existing dependency deprecation warnings remain; diagrams were
not rendered and no live/model/load result is inferred.

Focused second review inspected auth filters on both joined tables, scope and expiry
binding, literal query semantics, source quote offsets, missing-date/label handling,
sync lock order and sanitized lock-timeout behavior. Lock waits are bounded to one
second and each statement to three seconds. The index supports owner/date selection;
large-corpus substring search latency is still a staging gate, not a benchmark claim.

Migration `b7180d3f9e62` follows `a6417c29d805`. It adds only the search index;
downgrade drops only that index without deleting data. Apply during a maintenance
step with writers stopped, since a normal index build can block writes. No cloud
or live mailbox deployment/testing occurred. Next: B09 persistent entity/commitment
provenance/corrections and natural-language read planning, then B10 integration.
