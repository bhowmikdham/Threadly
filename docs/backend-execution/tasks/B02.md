## Implementation sequence

1. Implement proposed action/approval/job/attempt tables or consistent model placement in existing models.py. Use composite owned FKs, version/state checks, unique proposal/approval keys and one active dispatch attempt.
2. Implement pure transition rules and task-first locking helpers; retain exact immutable payload/hash and references. No provider client or external dispatch in this slice.
3. Coordinate draft edits with pending-action supersession using task → action lock order. After dispatch-intent cutoff, show the old action as possibly executing rather than claiming recall.
4. Define account/thread deletion handling for in-flight/unknown actions before adding cascading FKs. Keep new dispatch disabled; record minimal reconciliation-retention decision and pending policy gate.
5. Migration must preserve every existing artifact UUID, review and legacy draft row; refuse destructive downgrade when action history exists.

## Acceptance assertions

Implement independent tests for these behaviors. Record each assertion in the checkpoint;
do not mark a live assertion passed using only a mock. Apply all relevant QUALITY-GATES checks.

- **B02-A1:** Cross-owner action/approval/attempt insertion fails in service and DB constraints; unknown IDs do not leak existence.
