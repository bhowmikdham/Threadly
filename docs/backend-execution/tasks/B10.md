## Implementation sequence

1. Introduce bounded task steps with ordinal/DAG, owned typed inputs/outputs, state, retry budget and pinned per-step release. Validate entire supported operation sequence before starting.
2. Migrate artifact identity to explicit streams and a task final-result pointer as DESIGN D5. Preserve all existing UUIDs, draft revision numbers, reviews and action bindings.
3. Checkpoint successful read/generated steps; retries reuse unaffected outputs and recompute only invalidated dependencies. Keep external approvals/actions outside autonomous step execution.
4. Map intermediate versus final artifacts/events explicitly; allow lookup → reply/compose and later availability → draft without publishing intermediate output as final success.
5. Reject unsupported/reversed/cyclic sequences; one task's context does not authorize another's result refs. Bound steps, token/tool calls and total time.
6. Version the compound planner separately from historical routes. Preserve all explicit user clauses, negations and outputs; multi-label classifier scores are advisory and never select arbitrary Flow IDs. Implement the summary + scheduling + reply dependency graph in docs/master-workflow.md only when its whole handler set is installed.

## Acceptance assertions

Implement independent tests for these behaviors. Record each assertion in the checkpoint;
do not mark a live assertion passed using only a mock. Apply all relevant QUALITY-GATES checks.

- **B10-A1:** Lookup succeeds then generation fails: retry reuses valid lookup checkpoint and publishes one final result stream.
- **B10-A2:** Old draft history/review/action refs survive migration; latest task points to final artifact rather than largest unrelated revision.
- **B10-A3:** Cancel/lease replacement during any step fences publication; duplicate workers cannot double-publish step outputs.
- **B10-A4:** Changing a selected source invalidates dependent outputs but cannot mutate historical artifacts or approved outgoing payload.
- **B10-A5:** Every installed compound pair has end-to-end replay; unsupported full plans execute zero partial steps and return clear outcome.
- **B10-A6:** Summary + three meeting slots + reply: preserve all three requested outcomes; reply consumes validated summary/slot refs as requested; incomplete Calendar capability causes zero partial execution before preflight succeeds. Enable this scenario only with B12/B13 gates.
- **B10-A7:** Multi-label order does not determine step order. Negated reply/send never executes; a request to include the summary in the reply creates the matching dependency; separate summary-for-user output remains separate.
- **B10-A8:** Summary succeeds but Calendar fails: task remains incomplete, no slot-bearing reply is generated, and retry reuses only still-valid outputs. Stale slots invalidate dependent drafts; no invented free time or automatic send.
