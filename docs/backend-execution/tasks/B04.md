## Implementation sequence

1. Implement GET action, approve/reject/cancel contracts from DESIGN D2 with strict identity/version/hash/request ID checks and expiry policy.
2. Approval loads stored payload; no replacement action arguments allowed. Persist approval and outbox enqueue in one transaction; revalidate latest draft/context/capability under ordered locks.
3. Support idempotent retries after outcomes advance; reject changed request bodies. Store events without body, addresses, tokens or full hashes that are unnecessary in logs.
4. Before dispatch, cancellation/rejection can close pending work. After dispatch intent, record cancellation requested and return honest executing/unknown status.
5. Keep public approval unavailable until the executor is installed/enabled; exercise internal enqueue with a fake dispatcher. Mark reviewed never implicitly calls approve.

## Acceptance assertions

Implement independent tests for these behaviors. Record each assertion in the checkpoint;
do not mark a live assertion passed using only a mock. Apply all relevant QUALITY-GATES checks.

- **B04-A1:** Concurrent duplicate approvals produce one approval/job; same key/different hash conflicts; wrong version/hash cannot enqueue.
- **B04-A2:** Approval racing draft edit or expiry is serialized: only the still-valid exact version can be queued.
- **B04-A3:** Queue failure rolls back approval, and approval failure creates no orphan runnable job.
- **B04-A4:** Cross-owner IDs, injected replacement recipients/body, expired/rejected/superseded actions and missing scope fail.
- **B04-A5:** Cancel before dispatch suppresses send; cancel after cutoff cannot report not-sent without evidence.
