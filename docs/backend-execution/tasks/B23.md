## Implementation sequence

1. Implement bounded STT/TTS proxy with declared provider/config, file limits, consent/privacy and sanitized error handling.
2. Bind transcription as user input to task/context with uncertainty markers; names/addresses/dates with low confidence require confirmation.
3. Route typed and voice intent through the same API/worker; no transcript phrase bypasses Send/event approval.
4. Add optional playback controls and retention policy without logging raw sensitive audio/transcripts.

## Acceptance assertions

Implement independent tests for these behaviors. Record each assertion in the checkpoint;
do not mark a live assertion passed using only a mock. Apply all relevant QUALITY-GATES checks.

- **B23-A1:** Mistranscribed recipient/date forces confirmation; no automatic recipient guessing.
- **B23-A2:** Equivalent typed/voice instructions yield equivalent bounded routes and source bindings.
- **B23-A3:** Upload limits, unsupported media, upstream timeout and cancellation behave honestly.
- **B23-A4:** Audio/text consent and deletion are honored; voice cannot approve unseen exact payloads.

## External integration gate

Authorized voice provider/keys and UI integration plus live transcription evaluation.
