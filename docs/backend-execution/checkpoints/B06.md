## Implementation and decisions

`actions/gmail_reconciliation.py` performs only fixed-endpoint GETs: verify profile,
search bounded Sent pages by saved RFC Message-ID/time, then compare one candidate's
raw MIME semantically. Missing Bcc, mismatches, duplicate/incomplete results and
unrecognized normalization stay unknown. `actions/reconciliation.py` owns persisted
rounds, read leases, account fencing, observations and atomic result publication.
It runs independently of write enablement in the dedicated action worker.

Three read rounds maximum, 30/120-second delayed retries; a crashed read consumes
a round and can reclaim only under that budget. Exhaustion stays unknown/manual.
No DB transaction spans token/provider HTTP. Stale completion never overwrites a
terminal action. Compatible late dispatch observations are retained, conflicting
ones prevent an inferred success. No automatic resend or manual force-failed API.

Public action status adds nullable recovery guidance/count/due/code. Proposals,
approval checks and dispatch preflight block another send from the same task while
an earlier action is executing/unknown, including after edits or from preexisting
approved previews. Historical proposal replay remains available. A definite
rejection requires a new preview and independent approval, never job resurrection.

Staging deploy now stops both workers before backup/migration and starts them with
the same API image, checking running containers. Writes remain code-gated and
preflight rejects a true write flag until controlled verification. Recovery reads
are default off. CI additionally runs the offline EC2 deployment test suite.

and live checklist: [email action runbook](../../email-actions.md).

## Focused second review

- Owned task → action → account → job/attempt order. Claims lock task with SKIP
  LOCKED; all network transactions are released. Only original Google subject and
  actual Gmail read grants can recover; scope/account changes fence publication.
- Recovery uses historical bytes, not the edited draft, and does not require an
  unexpired old approval or current send grant. It cannot authorize a new write.
- Durable read rounds/observations are separate from B05 preflight attempts; job
  kind never changes back to dispatch. Empty/partial results cannot prove absence.
- Search accepts only backend UUID Message-IDs; fixed URLs, validated IDs, bounded
  pages/body/time and no redirects. Tokens, raw message content and provider error
  strings do not enter evidence/events/API error envelopes.
- One plain-text candidate must match saved semantics, including Bcc when present.
  Byte changes from encoding/folding/line endings may normalize; content whitespace
  never does. Any unsupported provider normalization remains manual/unknown.
- Result evidence merges current late observations and updates attempt then action
  under existing database guards. A failed commit is recoverable without a POST.
- The same-task resend guard uses the same task lock as dispatch/approval; it does
  not claim deduplication across independently created tasks or provider delivery.
- API keeps legacy send at 501 and new approval disabled. Live rollout still needs
  controlled new-mail/reply/recipient evidence, explicit UI, monitoring and retention.
