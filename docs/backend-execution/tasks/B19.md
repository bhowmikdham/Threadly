## Implementation sequence

1. Add redacted structured metrics/events for queue age, lease recovery, routing errors, upstream failures, action unknown backlog, scope failures and budgets; correlation IDs must not contain mail text.
2. Implement feature flags/kill switches per intent and write type, configurable limits, readiness dependencies and worker health. Disabling writes prevents new dispatch but allows reconciliation reads.
3. Define and implement approved retention/deletion lifecycle for snapshots/artifacts/actions/tokens/vectors, preserving minimum unknown-attempt recovery state only under explicit policy.
4. Move large-mailbox sync to bounded durable background work with pagination/checkpoints/backpressure; keep sync-version fencing and deletions consistent.
5. Update deployment docs for actual Bedrock mode, separate API/generation/action workers, migrations/backups/restore/rollback and concurrency sizing. Add CI coverage for new schemas/assets/config as needed.

## Acceptance assertions

Implement independent tests for these behaviors. Record each assertion in the checkpoint;
do not mark a live assertion passed using only a mock. Apply all relevant QUALITY-GATES checks.

- **B19-A1:** Synthetic private mail/token content never appears in logs/events/metrics; observability failures cannot corrupt action state.
- **B19-A2:** Kill switch during queued and dispatched work stops only eligible new writes and preserves unknown outcome evidence.
- **B19-A3:** Retention skips active dependencies, deletes expired owner data correctly and cannot cascade away unresolved attempts contrary to policy.
- **B19-A4:** Interrupted large-mailbox sync resumes without losing cursor/order or overwriting newer sync; memory/concurrency limits are exercised.
- **B19-A5:** Backup/restore and migration rehearsal on disposable data demonstrate preserved tasks/actions and safe recovery without duplicate writes.
