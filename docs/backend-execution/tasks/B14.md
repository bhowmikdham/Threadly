## Implementation sequence

1. Add negotiation identity linked to owner/thread, offer revision, selected slot, related task IDs and optional created event. This outlives a single generation task.
2. Extract scheduling constraints to strict proposals, validate/clarify temporal fields through B08 and run B13. Persist assumptions and unknown invitee availability.
3. Create schedule_options or availability answer artifacts, then optional draft using stored slot labels/IDs only. Entire availability→draft plan must be installed.
4. Bind selected offered option to exact negotiation/offer/source version; a later email selection is a proposal requiring user confirmation, not approval to book.
5. Offer expiry/new replies/preference changes invalidate affected choices and require recheck; sending a slot offer still uses B03–B06.
