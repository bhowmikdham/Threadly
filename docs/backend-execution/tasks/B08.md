## Implementation sequence

1. Add durable questions and append-only user input records with question identity, kind/schema, task version, selected refs, source/input version and request hash.
2. Implement POST /assistant/tasks/{id}/inputs; validate owned current question and typed input under task lock, consume once and atomically requeue with new effective input/checkpoint.
3. Keep original instruction/request hash immutable; pin context/reference and release changes explicitly. Invalidate only dependent route/step outputs and require fresh source capture when needed.
4. Support repeated clarifications and user cancellation; reject answers to finished/expired/stale questions. Raw yes is never send approval.
5. Version worker/route behavior and maintain previous queued-release support. Return current task and event cursor for frontend continuation.

## Acceptance assertions

Implement independent tests for these behaviors. Record each assertion in the checkpoint;
do not mark a live assertion passed using only a mock. Apply all relevant QUALITY-GATES checks.

- **B08-A1:** Duplicate/concurrent answers consume one question and queue once; changed payload with same request ID conflicts.
- **B08-A2:** Stale question/task version, wrong owner and unrelated choices cannot change task state.
- **B08-A3:** Answer after cancellation or after a newer question fails; restart during input commit cannot lose/duplicate effective input.
- **B08-A4:** A timezone/recipient answer continues the original scheduling/drafting goal rather than being classified as unrelated new work.
- **B08-A5:** Source changes require fresh binding; continuation cannot retain a stale send approval or authorize writes.
